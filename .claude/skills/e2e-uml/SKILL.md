# End-to-end test under User-Mode Linux

Full documentation is in tests/e2e/README.md. This skill is the working
summary.

## Run

```sh
T6_E2E_WORK=<dir with ~3 GB free> T6_BUILDENV=<buildenv.sh or empty> \
T6_PYTHON=<python with Pillow+numpy> tests/e2e/run.sh [--patch fix.diff]
```

- A cold run builds a UML 7.2 kernel (~10 min); a warm run takes ~2 min. Exit
  status 0 means pass. Output goes to `$T6_E2E_WORK/out`: frames, `log.jsonl`,
  dmesg, stats.
- Needs: gcc with static glibc, make, curl, xz, patch. No root and no hardware.
  On Fedora, `glibc-static` provides static glibc.
- Don't run it on a live USB: it needs GBs of disk and the RAM overlay is
  small. Run it on an installed machine or in WSL.
- `--patch` applies a `-p1` diff (with `a/src/...` paths) to a *copy* of src/,
  for trying fixes without editing the tree.

## What it covers

Inside UML: KUnit (`mct_t6_test.ko`), then two passes, fence (the emulator
reports frame-done) and no-fence. Each pass does:

1. probe and fbdev;
2. `t6drm`: SETCRTC 1080p, 5 DIRTYFB rectangles, CURSOR2 set, move, negative
   move and hide, then CRTC off;
3. emulator unplug, driver disconnect, re-probe.

`verify.py` checks:

- the exact 0x12/0x31/0x03 sequence and the 1080p60 table record;
- every bulk and video header field;
- that frames decode and match the drawn images, with PSNR calibrated against
  libjpeg;
- the cursor shape and position requests;
- no video traffic during cursor-only updates;
- that the debugfs stats agree with the emulator's counts;
- a clean dmesg: no WARN, KASAN or lockdep reports.

## Extending

- **New protocol behaviour:**
  1. Teach `t6emu.c` to answer and validate it.
  2. Log it as a `log.jsonl` event.
  3. Assert on it in `verify.py`.
- **New userspace scenario:** add a step to `t6drm.c`, which writes
  `manifest.json` and expected images, and handle it in `verify.py`.
- **Hardware findings:** when the real dock answers differently from the
  emulator (status bytes, EDID behaviour, interrupt timing), update the
  emulator to match. That way the regression test reflects reality.
- **Emulator data:** `t6emu_data.h` is generated by `gendata.py` from
  `docs/research/windows-captures/`. Regenerate it; don't hand-edit.

## Lessons it has already taught

It found five driver bugs that no unit test could have found. The
CRTC-disable event bug escalated to a KASAN use-after-free on unplug. Run it
before calling any KMS or teardown change done.
